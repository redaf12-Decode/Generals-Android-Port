# Development Diary - November 2026

---

## 2026-11-04: The financial-support system is gone

Owner's request: no card, message, window or link asking for financial support should reach the
player anywhere in the app. The obvious part was one call -- `buildSupportSection(page)` on the
Help page -- but the support UI was not self-contained in `SetupActivity`: its text came from
`update/support.json`, published on the `updates` branch and rendered at runtime by `SupportLinks`,
with `UpdateManager` downloading and digest-checking it against the signed manifest. Removing only
the Help-page call would have left the popup (`maybeShowSupportPopup`, shown once per published id)
and the download path live, so the whole chain went together.

Gone, in `android/`:

- `SetupActivity`: the `buildSupportSection` call, and the methods `buildSupportSection`,
  `renderSupportBlocks`, `maybeShowSupportPopup`, `copySupportAddress` and `openSupportLink`; both
  `maybeShowSupportPopup()` call sites (in `onCreate` and in the update-check callback, where
  `r.supportUpdated` also forced a Help-page refresh); the `PREF_SUPPORT_POPUP_SEEN` key.
- `UpdateManager`: `applySupport()`, the `supportUpdated` field and its assignment, and the javadoc
  bullet. A manifest that still carries a `"support"` entry is now simply ignored -- the signed
  manifest on the branch needs no change for the app to stop showing anything.
- `SupportLinks.java` (370 lines) deleted; `SetupActivity` was its only consumer.
- `setup_support_popup_later` removed from all 13 locale `strings.xml`.
- `ic_gzh_heart.xml` deleted. `ic_gzh_copy` stays -- `NetworkDiagnosticsActivity` and other rows use
  it, so it was never support-specific.

And outside `android/`, so the source stops carrying the payload at all:

- `update/support.json` deleted, and with it the `--support` option and the `support/<digest>.json`
  publishing block in `scripts/update/publish-update.py` (the manifest no longer gets a `support`
  key). Verified by running the script: it produces `manifest.json` and `datapack-manifest.json`
  and nothing else.
- `docs/HOWTO/PUBLISH_UPDATE.md`: the "Support card" bullet and the "Monthly heroes" section.
- `docs/port/ANDROID_PORT.md`: the support-card bullet and "support the project" in the Help-page
  description.

633 lines removed from the app in one commit, and none added. Checked by compiling the whole Java
shell with `javac` against `android-35.jar` plus the material/core/appcompat/cardview jars -- zero
errors, and the pre-change tree compiles clean the same way, so the removal is not hiding a
regression. The two deleted resources are exactly the two that disappear from the generated `R`.

**Still to do, and it needs the owner:** the `updates` branch already published carries a `support`
entry naming a `support/<digest>.json`. A launcher built before this change will keep showing the
card until the next settings publish, and only a publish can withdraw it -- the code change alone
cannot. Publish settings once (`publish-update.py --out ...`, then `push-updates-branch.sh`, then
**Actions → Sign update**) to drop the entry from the live manifest.

The historical October diary and the `v1.4.0`/`v1.4.1` release notes still describe the support card
as it was; they are a record of what shipped then, so they were left alone. The README's "Support
the project" and "Heroes of the project" sections are the project's own front page and are also
untouched -- that is the owner's call, not a code change.
